Cloudflare Pages Edge Powered

ImagEngine

High-performance edge image optimization, format conversion, and SVG rasterization proxy running natively on Cloudflare Pages Functions with WebAssembly.

⚡ Multi-Engine Architecture

Uses @cf-wasm/resvg for crisp SVG vector rendering and @cf-wasm/photon (Rust WASM) for high-speed raster manipulation & WebP encoding.

🛡️ Edge Caching & Anti-DDoS

Integrated with caches.default Cache API + 1-year immutable CDN headers. 404 errors feature 300s negative caching to protect upstream quotas.

🔄 Zero-CPU Passthrough

When the original extension matches the requested format without transformations, assets stream directly byte-for-byte with 0ms CPU penalty.

🔧 Auto-Healing URLs

Smart URL parser automatically resolves glued query parameters missing ampersands (e.g. ?h=630w=450 → ?h=630&w=450).

1. URL Syntax & Routing

ImagEngine supports both Slug-based and Query Parameter based routing:

Pattern A: Slug-based Extension URL (Recommended for SEO & Clean URLs)
https://<domain>/[subdomain.]<tenant>/<path>-<origExt>.<targetExt>[?params]
Pattern B: Dot Slug URL
https://<domain>/[subdomain.]<tenant>/<path>.<origExt>.<targetExt>[?params]
Pattern C: Direct Path with Format Query Parameter
https://<domain>/[subdomain.]<tenant>/<path>.<origExt>[?format=<targetExt>&params]

2. Tenant Origin Mapping

The first path segment identifies the target upstream domain, with optional subdomains:

Tenant Key Resolved Origin Domain Example Tenant Path
tn topnepali.com /objects.tn/... → objects.topnepali.com
ginfo grisma.info.np /ginfo/... → grisma.info.np
gcom grisma.com.np /object.gcom/... → object.grisma.com.np
gname grisma.name.np /gname/... → grisma.name.np
ecn election.gov.np /ecn/... → election.gov.np

3. All Possible Scenarios & Practical Examples

Scenario 01

Social Media OG Image (SVG → WebP at 1200x630)

Render dynamic Open Graph SVG cards (like news, candidate cards, typography banners) into crisp WebP for Facebook, Viber, and WhatsApp crawlers.

GET /objects.tn/wp-content/uploads/2026/10/banner-svg.webp?w=1200&h=630&fit=cover

Under the hood: Resvg renders vector fonts and graphics into pixel-perfect PNG, then Photon encodes to WebP at q=85 (~35KB output). Result is edge-cached for 1 year.

Scenario 02

Candidate / User Profile Avatar (Square Crop Anchored to Face)

Easily create 256x256 square avatars anchored to the top so heads and faces are never chopped off.

# Quick avatar preset:
GET /ecn/candidates/kamal-png.webp?avatar=1

# Or custom avatar dimensions:
GET /ecn/candidates/kamal-png.webp?w=300&h=300&fit=cover&position=top
Scenario 03

Proportional Aspect-Ratio Resizing (Single Dimension)

Supply either width or height alone; ImagEngine automatically calculates the other dimension maintaining exact aspect ratio without distortion.

# Resize to 500px width (auto height):
GET /object.gcom/uploads/photo.jpg?w=500&format=webp

# Resize to 400px height (auto width):
GET /object.gcom/uploads/photo.jpg?h=400&format=webp
Scenario 04

Fit Modes: 600x600 from a 1000x1120 Portrait Photo

Control exact cropping and fitting behavior when providing both width and height:

Fit Parameter Behavior Example URL
fit=cover Recommended: Crops excess edges to fill the exact 600x600 box without stretching. ?w=600&h=600&fit=cover
fit=contain Preserves full image within 600x600 bounds (aspect ratio preserved, no cropping). ?w=600&h=600&fit=contain
fit=fill Forces image to fill 600x600, stretching/distorting if aspect ratio differs. ?w=600&h=600&fit=fill
fit=inside Scales down to be as large as possible while staying completely within dimensions. ?w=600&h=600&fit=inside
Scenario 05

Crop Alignment (Position Anchoring)

When cropping with fit=cover, control which part of the image is kept:

?w=600&h=600&fit=cover&position=center   # Default: center crop
?w=600&h=600&fit=cover&position=top      # Top anchor (perfect for portraits)
?w=600&h=600&fit=cover&position=bottom   # Bottom anchor
?w=600&h=600&fit=cover&position=left     # Left anchor
?w=600&h=600&fit=cover&position=right    # Right anchor

Scenario 08

Edge-Level Route Defense & 404 Shield (Zero-Worker Hit)

Protection against quota drainage, scanning bots, and DDoS flooding:

  • Random/Junk Paths (e.g. /randoafaslkdaf, /wp-login.php): Filtered immediately at the Cloudflare Edge CDN using _routes.json whitelist. Never touches or invokes the Worker function (0 Worker Requests, 0ms CPU).
  • Deleted/Missing Upstream Images: When an image does not exist on origin, the 404 response is negative-cached for 300 seconds (5 minutes). Subsequent requests are absorbed entirely by Cloudflare CDN cache. 
# Edge Routing Defense (_routes.json):
Only valid tenant routes (/tn/*, /*.tn/*, /ginfo/*, /gcom/*, /gname/*, /ecn/*) invoke the Worker.
All non-image paths are dropped by Cloudflare Edge as instant 404s without consuming Worker quota!
Scenario 09

10MB+ Large Image & Memory Protection

Cloudflare Workers enforce a 128 MB RAM limit. ImagEngine incorporates defensive safeguards:

  • Passthrough: Large images requested in their original format bypass WASM entirely and stream with near-zero RAM usage.
  • 36 Megapixel Safe Guard: If a decoded raster exceeds 36 Megapixels (~144 MB raw buffer), ImagEngine safely returns 413 Payload Too Large instead of crashing the Worker process.
  • Deterministic Memory Freeing: Every intermediate Photon and Resvg WASM instance is explicitly freed using img.free() to prevent heap leakage.
Scenario 10

Auto-Healing Malformed Query Strings

Sometimes CMS themes, social scrapers, or third-party links concatenate query parameters without standard ampersands (e.g. ?h=630w=450 instead of ?h=630&w=450).

# Legacy/Broken URL from scraper:
GET /objects.tn/banner-webp.webp?h=630w=450

# Automatically normalized internally to:
GET /objects.tn/banner-webp.webp?h=630&w=450  → Exact 450x630 output!

ImagEngine automatically detects and normalizes these parameters on the fly, preventing unwanted distortions without requiring any code changes on the caller's side.
